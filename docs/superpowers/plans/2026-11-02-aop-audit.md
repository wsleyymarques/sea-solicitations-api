# AOP Audit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Auditar escritas relevantes no PostgreSQL sem copiar segredos ou mudar respostas de negocio.

**Architecture:** Annotation nos metodos dos casos de uso; aspect classifica contexto seguro, invoca o metodo e grava sucesso/falha por um writer transacional independente.

**Tech Stack:** Java 21, Spring Boot AOP, Spring Security, Spring Data JPA, PostgreSQL, JUnit 5.

**Spec:** `docs/superpowers/specs/2026-11-02-aop-audit-design.md`

## Global Constraints

- Preservar alteracoes locais e nao criar commit automatico.
- Nao registrar senha, token, comentario, endereco ou payload integral.
- Nao substituir a excecao de negocio por erro de auditoria.

## Review Focus

- Falha de negocio grava `FAILURE` mesmo com rollback.
- Ator autenticado prevalece sobre IDs de comando.
- Cadastro de analista grava o evento de cobertura sem duplicar cadastro.
- AOP realmente intercepta beans Spring declarados por interface.
- Falha do writer nao muda o resultado do caso de uso.
